# JT65 接收灵敏度拓展（在原实现之上新增，原有路径未改动）

本目录原有内容保持可用，本文档只描述**新增**的功能、用法与实测结果。

## 1. 新增了什么

### 新增文件

| 文件 | 作用 |

| 文件 | 改动 |

| `matlab/jt65_lab/JT65LabApp.m` | 新增"解调方式"下拉框；摘要面板显示解调方式。默认值与原行为一致 |

## 2. 实测结果（真机录波 + 软件 AWGN，2500 Hz 参考带宽）

录波：`data/jt65_live_20261013_153253_859`（11025 S/s 标准时序，符号 371.5 ms）。
每档 12 次，加噪口径与 `exp34_jt65_snr_test` 一致。

### 单帧，两种解调方式

| SNR | 非相干+硬（基线） | 相干+硬 |
|---|---|---|
| −20 dB | 100% | 100% |
| −21 dB | 100% | 100% |
| −22 dB | 58% | 67% |
| **−23 dB** | **8%** | **75%** |
| −24 dB | 0% | 8% |
| −25 dB | 0% | 0% |

**结论**

- **相干检测：约 +1.2 dB**（50% 门限从约 −22.1 dB 移到约 −23.3 dB）。理论值 +1.65 dB，
  差值来自相位参考估计误差。
- **软判决：0 增益**，与硬判决逐点完全相同（试过、量过、已删除，原因见第 3.4 节）。
- 相干在任何档位都不比基线差（有回退保护，见 3.2）。

### 多帧平均（非相干累加）

| 帧数 | 等效增益 | −26 dB | −30 dB |
|---|---|---|---|
| 1 | 0 dB | 0% | 0% |
| 2 | +3 dB | 8% | 0% |
| 4 | +6 dB | 67% | 0% |
| 8 | +9 dB | **100%** | 0% |

**结论**：−26 dB 下 1 帧完全解不出，4 帧 67%、8 帧 100%，与 `10·log10(N)` 规律一致。

**但有地板**：−30 dB 下即使 8 帧（等效 −21 dB）也是 0%。原因是**逐帧同步先失效**——
每帧的同步音检测本身需要一定信噪比，帧同步错了，累加的就是错位的能量。
改善方向是"多帧联合同步"（把同步搜索也跨帧相干累加），当前未实现。

### 真机验收（B210 347380A，2026-10-16，慢速时序）

发射增益逐档降低各采 4 帧，逐帧用两种解调方式回放。采集目录
`data/jt65_loop_20261016_092515_936` 等，报告 `data/jt65_hwtest_20261016_092451_762/`。

| 发射增益 | 基线（非相干+硬） | 相干+硬 | 非相干+软 | 相干+软 |
|---|---|---|---|---|
| 30 dB | 4/4（符号错 0） | 4/4（0） | 4/4（0） | 4/4（0） |
| 20 dB | 4/4（0） | 4/4（0） | 4/4（0） | 4/4（0） |
| 10 dB | 4/4（0） | 4/4（0） | 4/4（0） | 4/4（0） |
| **6 dB** | **0/8（32）** | **3/8（36）** | 0/8（32） | 3/8（36） |
| 4 dB | 0/4（44） | 0/4（46） | 0/4（44） | 0/4（46） |

- **默认路径回归**：快速时序、相干关、硬判决，符号错误 0/63，消息正确 —— 改动未影响原有行为。
- **6 dB 那组实测 ≈ −23.4 dB**（2500 Hz；400 Hz 档估到 −15.4～−17.2 dB）。
  基线 0/8 解出，**相干 3/8** —— 这是相干检测 +1.2 dB 在真实空口上的直接体现。
- **4 dB 那组实测 −25.2 dB**，已低于非相干硬判决的 −22.8 dB 门限，四帧单帧全挂
  （43～49 个符号错误），相干也救不回（相位参考本身估计不准）。
- **多帧平均在两组的低增益点都救回了消息**：
  - 4 dB 组 4 帧（+6 dB）→ 符号错误 18/63，解出 `1011010`；
  - 6 dB 组 8 帧（+9 dB）→ **符号错误 0/63，解出 `1011010`**（单帧 8 帧全部失败）。
  这是"用观测时间换灵敏度"在真实空口上最直接的演示。

## 3. 实现要点

### 3.1 相干检测：一个被忽略的相位项

JT65 是相位连续 FSK，音调间隔 `df` 与符号时长 `T` 满足 `df·T ≈ 1`，所以除一个公共复参考
`a` 外，各符号起始相位基本确定：

```
phase_k = phase_0 + (k-1)·2π·fSync·T
```

**但实测对不上。** 同步符号完全吻合（相干度 0.998），数据符号却对不上，符号错误接近随机。

查下来是**定时残差**：同步搜索的时间网格是 16 个抽样，落在符号中间时会残留一个
`tau_off`，给每个符号再叠加一个**与频率成正比**的相位：

```
phase_k = phase_0 + (k-1)·2π·fSync·T + 2π·(f_k - fSync)·tau_off
```

实测 `tau_off` 在干净录波上是 21.8 抽样（3.96 ms，符号长度的 1%），低信噪比下同步落点
再偏，最大见到 11.6 ms。加上这一项后，拟合相干度从 **0.4643 → 0.9980**，残差相位
标准差 0.063 rad。

`psi = 2π·tau_off` 的估计方式：用**非相干判决当导频**，在 ±0.20 rad/Hz（±32 ms）范围内
搜索使 `|Σ pilot·exp(-i·f·psi)|` 最大的 `psi`。不需要发送参考。

> 走过一次弯路：最初用"各符号相干度量最大值之和"作盲搜索准则。低信噪比下该准则会被
> 噪声带偏，−20 dB 处锁到错误 `psi`，符号错误反而从 8/63 升到 38/63。导频法没有这个问题。

### 3.2 相干路径的回退保护

`psi` 搜索偶尔仍会锁错位置，此时相干判决的符号错误会**高于**非相干判决。为此解调器把
非相干判决一并返回；主判决译码失败时，`decodeFrame` 再用非相干判决试一次。这保证
**相干路径只增不减**（实测 −20 dB 有 2/20 帧走回退，最终解出数与非相干持平）。

### 3.3 多帧平均

逐帧独立做时/频同步与解调，得到每帧的 64×63 能量矩阵，把**同载荷**的各帧矩阵相加再译码。
非相干累加使信噪比按 `10·log10(N)` 提升。

载荷分组：二进制 7 bit 模式每帧都重复（`GroupModulo=1`）；ASCII 文字模式按字符循环
（`GroupModulo=字符数`，默认从 `tx_reference.mat` 的 `sequenceLength` 自动判定）。

### 3.4 软判决：试过，0 增益，已删除

代码里曾加过一个 `DecoderMode="soft"`（确定性 Chase：把最不可靠的 `e` 个位置标记为擦除并
枚举候选值，再用重编码能量打分选最优），**实测与硬判决逐点完全相同，软件和真机都是 0 增益，
因此已删除**。原因如下。

RS(63,12) 能纠 25 个符号错误（占 n 的 40%），编码已经很强。Chase 式擦除译码中，其余位置可纠
`(51-e)/2` 个错误——**擦除与可纠错误是 2:1 交换**，总量只从 25 涨到 `25.5+e/2`。

实测在 −22 dB（中位 27 个符号错误）：软判决完整跑了 9 次纠删 + 4096 次 Chase 枚举，
**一次都没解出来**。原因是 27 个错误中大约只有 7 个落在被擦除的 12 个位置上，剩下 20 个
超过 `(51-12)/2 = 19` 的容量。

理论上限也只有 +1.05 dB（等效纠错能力从 25 提到 33），而且那需要**真正的软判决译码器**
（如 Koetter-Vardy 或 Guruswami-Sudan 列表译码），MATLAB 没有现成实现，工程量远大于收益。

结论：**软判决在这个码上不是有效的杠杆**。真正有效的是相干检测和多帧平均。

## 4. 理论对照

| 项 | 2500 Hz 带宽下的门限（50% 整帧正确） |
|---|---|
| 非相干 64-FSK + 硬判决 RS(63,12) | −22.76 dB |
| **相干 64-FSK + 硬判决 RS(63,12)** | **−24.41 dB** |
| 相干相对非相干的增益 | **+1.65 dB** |
| 软判决上限（等效 t=25→33） | +1.05 dB |
| Shannon 极限（JT65 速率 72 bit/46.8 s，带宽 177.6 Hz） | ≈ −33.7 dB |
| 标准 JT65（WSJT-X 官方） | −25 dB |
| Q65-60A（软判决 LDPC + 相干） | −27.6 dB |
| Q65-300A（5 分钟） | −33.8 dB |

非相干/相干的理论值由数值积分算出（非相干用特征函数积分，相干用高斯 CDF 积分）。

**距离标准 JT65 的 −25 dB 还差约 1.7 dB**，主要来自：AP 先验译码、更好的同步与信道估计。
**距离 Shannon 还有约 9 dB**，但那是 65-tone FSK 这类调制的固有代价（一半时间发已知同步
图案、非容量逼近调制），不是调参能补的。

## 5. 怎么验收

### 不需要硬件（软件加噪扫描，约 10 分钟）

```matlab
addpath('/Users/limit/Documents/MATLAB/USRP实验包/matlab/jt65_lab');
report = exp34_jt65_feature_sweep( ...
    "/Users/limit/Documents/MATLAB/USRP实验包/data/jt65_live_20261013_153253_859", ...
    Levels=-20:-1:-25, Trials=12, AverageFrames=[1 2 4 8], AverageLevels=[-26 -30]);
```

输出四组单帧对比表和多帧平均表，结果同时存到录波目录下的 `feature_sweep_时间/`。

### 需要硬件（真机验收）

先确认 B210 已连接（`uhd_find_devices` 能看到），天线接好，然后：

```matlab
addpath('/Users/limit/Documents/MATLAB/USRP实验包/matlab/jt65_lab');
report = exp34_jt65_hardware_test();     % 默认 TxGains=[30 24 18]，每组 3 帧，慢速时序
```

流程：默认路径回归 → 逐档降低发射增益各采一组 → 逐帧用两种解调方式分析 → 对最低增益那组做
多帧平均。日志与 `hwtest_report.mat` 存到 `data/jt65_hwtest_时间/`。

参数可调，例如：

```matlab
report = exp34_jt65_hardware_test(TxGains=[30 26 22], FramesPerGain=4, RxGain=40);
```

**安全**：默认 435 MHz、发射增益不超过 30 dB，接法与既有实验一致。请先确认当地无线电
规定并接好天线。
